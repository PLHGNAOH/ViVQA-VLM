Part 01

Problem & the Vietnamese Challenge

Given an image and a Vietnamese question about it, the system must generate a Vietnamese answer that is short, faithful to the image content, and spelled correctly with diacritics. Unlike classification or object recognition, VQA requires understanding the image, the language, and reasoning at the same time.

Research problem: adapt an open-source VLM (Qwen2.5-VL-3B) to answer Vietnamese questions — reading diacritic-bearing text in images correctly and answering correctly in Vietnamese — using PEFT (QLoRA) alone, on a single T4 GPU.

Where Does Vietnamese Differ from English?

V1
Reading diacritic-bearing text in images

Diacritics and diacritic-bearing letters (ă, â, ê, ô, ơ, ư, đ) are tiny strokes in an image. If the model misreads or drops a diacritic, the meaning changes (“má” (cheek) ≠ “mà” (but)). This is a perception error at the pixel level and cannot be fixed by text normalization.

Evidence: on ViTextVQA, removing diacritics lowers the F1 of every baseline model (Nguyen et al., ViTextVQA, §7.1).

V2
Wrong-language or wrong-format answers

VLMs pretrained mainly on English/Chinese tend to answer in English, mix English and Vietnamese (code-switching), or answer verbosely. In that case EM = 0 even though the model understood the content. For English this issue is almost absent because it is the model's primary language.

V3
Text order & word boundaries

Vietnamese whitespace separates syllables, not words (“thời gian” (time) is a single word). Text extracted from an image in the wrong order breaks words and changes the meaning.

Evidence: ordering OCR text top-left → bottom-right (TL-BR) improves most models on ViTextVQA (Nguyen et al., §6.4).

V4
Hallucination

The model answers fluently but with content that is not in the image (invented objects or invented text). There is no POPE-style hallucination evaluation for Vietnamese VQA yet (G4).

Preprocessing ≠ Research Problem

Preprocessing — a mandatory technical step, not a contribution
  • Unicode NFC normalization of questions and answers
  • Lowercasing, removing extra punctuation, collapsing whitespace
  • Apply the same normalization function to ground-truth answers and model outputs before computing metrics
  • Resize images by max_pixels
Research problem — the focus of the project
  • Read diacritic-bearing text in images correctly (V1, V3)
  • Answer in the correct language and format (V2)
  • Do not fabricate content (V4)
  • Achieve all of the above with PEFT only, on a T4 GPU

Actual reference point: zero-shot Qwen2.5-VL-3B reaches EM 38.3% · ANLS 55.9% on ViTextVQA (mirror, n=300, seed 42) — see Part 07.

Part 02

Research Gap

G1
English-biased Pre-training

VLM alignment is optimized for English — transfer to Vietnamese has not been studied closely.

Source: LLaVA-1.5 (Liu 2024) ↗

G2
Weak Vietnamese VQA, especially scene-text

Performance on ViTextVQA is low: OCR, Vietnamese diacritics and code-switching are not yet fully solved. The highest reported result reaches only EM 25.48%, while humans reach 88% (see Part 03).

Source: ViTextVQA (Nguyen 2024) ↗ · LLaVA-1.5 (Liu 2024) ↗

G3 — FOCUS
PEFT for Vietnamese VLM remains unexplored

No systematic study has applied LoRA/QLoRA to VLMs for Vietnamese VQA — this is the main gap of the project.

Basis: 3 Vietnamese VQA papers surveyed — none applies PEFT/QLoRA (see Literature Matrix).

G4
Hallucination not measured for Vietnamese

No hallucination benchmark (POPE-style) has been evaluated on Vietnamese VQA data.

Source: POPE (Li et al., 2023, EMNLP) · LLaVA-1.5 (Liu 2024) ↗

Comparison caveats

The reference points above use different metrics and setups (token-level F1; classification accuracy over a fixed label set), so they serve only to position the results and are not placed next to the team's numbers as direct comparisons. The team also computes token-level F1 as an auxiliary metric to cross-check against the ViTextVQA table.

What the team takes from prior work

Parameter efficiency has precedent

ViTextBLIP-2 trains only about 5% of the parameters yet outperforms full fine-tuning models → supports the team's QLoRA direction.

Vietnamese diacritics are a core problem

Removing diacritics lowers the performance of every model → V1 is a research problem, not just preprocessing.

OCR order affects results

TL-BR ordering improves most models → the team feeds OCR text into the prompt in TL-BR order.

Remaining gap

Among the works the team surveyed, none adapts a modern multilingual VLM (Qwen-VL family) with LoRA/QLoRA for Vietnamese VQA (G3).

Part 04

Research Questions

Four research questions guide the entire experimental study and ablation analysis.

RQ1
Zero-shot & prompting on Vietnamese data

How well do VLMs perform zero-shot on ViVQA/ViTextVQA, which Vietnamese error types (V1–V3) dominate, and how far does a Vietnamese prompt improve results? Measured with EM, VQA-Acc, ANLS.

RQ2 — FOCUS
How much does PEFT (QLoRA) improve over zero-shot?

How much does QLoRA improve over zero-shot / prompting — without full fine-tuning? This is the central question.

RQ3
Vietnamese OCR × QLoRA on ViTextVQA

Does putting diacritic-bearing OCR text, ordered TL-BR, into the prompt help read the text in the image correctly, and does it combine synergistically with QLoRA? Measured with ANLS.

RQ4
How does QLoRA affect hallucination?

After QLoRA adaptation, does the model fabricate more or less content? Evaluated in the POPE-vi style.

Part 05

Hypotheses (H1–H4)

Each hypothesis is tied to a specific Vietnamese problem (V1–V4) and tested by comparison with the reproduced baseline — same model, same split, same seed. Thresholds are taken from the literature and have not yet been measured on Vietnamese.

H1 QLoRA adapts to Vietnamese — QLoRA on Qwen2.5-VL-3B improves EM by ≥ +5 over the zero-shot result of the same model. (RQ2 · V1–V3)
H2 Vietnamese OCR — Putting diacritic-bearing OCR text, ordered TL-BR, into the prompt improves ANLS by ≥ +3 on ViTextVQA; combining it with QLoRA gives the best result. (RQ3 · V1, V3)
H3 Output-language constraint — A Vietnamese format prompt (short answer, with diacritics) improves EM by ≥ +3 and reduces the rate of wrong-language or diacritic-dropped answers. (RQ1 · V2)
H4 Reliability — QLoRA does not increase the hallucination rate (POPE-vi) relative to zero-shot. (RQ4 · V4)
No longer hypotheses — moved to measurement or ablation
  • 4-bit vs. 16-bit, VRAM reduction: this is an established property of QLoRA (Dettmers et al., NeurIPS 2023), not an answer to the Vietnamese problem → only VRAM, time and the number of trained parameters are reported for each run.
  • LoRA all-linear vs. attention-only, rank r: these are configuration choices → moved to a secondary ablation.
  • Shared adapter vs. a separate adapter per dataset: optional, done only if time permits.

Mapping to the Review 1 version: H1 → H1 · H6 → H2 · H7 → H3 · hallucination hypothesis → H4.

Part 07

Proposed Method & Pipeline

A single method is fixed. Every other component is an ablation to show which part produces the improvement.

PROPOSED METHOD
QLoRA on Qwen2.5-VL-3B-Instruct + Vietnamese prompt with OCR

The base model is frozen in 4-bit (NF4); only the LoRA adapters are trained on ViVQA and ViTextVQA. The input consists of the image, the question, the OCR text (ordered TL-BR, ViTextVQA only), and an instruction to answer briefly in Vietnamese with diacritics.

System Pipeline

Step 1
Data

ViVQA + ViTextVQA (official repos): images, questions, answers.

Step 2
Preprocessing

NFC, lowercase, answer normalization; resize images by max_pixels.

Step 3
OCR (ViTextVQA)

PaddleOCR / VietOCR → order TL-BR → cache as JSON per image, run once.

Step 4
Fixed splits

Official split; 1,200 val samples held out from the ViVQA train set and a 2,000-question ViTextVQA test subset (seed 42).

Step 5
Prompt builder

Combines image + question + OCR + Vietnamese instruction; truncates OCR to the token budget.

Step 6
Qwen2.5-VL-3B 4-bit + LoRA

Training: loss on answer tokens only, only LoRA is updated.
Inference: greedy decoding, small max_new_tokens.

Step 7
Post-processing & evaluation

Normalize outputs like the ground truth; EM, VQA-Acc, ANLS (+ auxiliary F1); POPE-vi; error analysis by question type and V1–V4; log seed, VRAM, time.

Step 8
Web prototype

Gradio: upload an image, ask in Vietnamese, show the answer, confidence and OCR text.

Prompt template (kept in Vietnamese — this is the exact text sent to the model): to be finalized through ablation on the dev set.

<ảnh> Văn bản trong ảnh (OCR, trái→phải, trên→dưới): {ocr_text} Câu hỏi: {question} Trả lời ngắn gọn bằng tiếng Việt có dấu, chỉ dùng thông tin có trong ảnh.

QLoRA in This Project

How QLoRA works
  1. Quantization: the model's base weights are compressed to 4-bit (NF4) and frozen — they are not updated.
  2. Attaching LoRA: each linear layer gets two extra small matrices A·B (rank r). Only A and B are trained — a very small fraction of all parameters (the exact number is logged in every run).
  3. Result: an adapter of a few tens of MB, attached to the base model at inference.

Source: Hu et al., LoRA (ICLR 2022) · Dettmers et al., QLoRA (NeurIPS 2023).

Why QLoRA only, not LoRA vs. QLoRA

The available GPU is a T4 16 GB (Colab), which does not support bf16. The estimated weights of a 3B model at 16-bit already take about 7–8 GB, before counting the activations of high-resolution images; at 4-bit about 2–3 GB.

→ QLoRA is a prerequisite for running on the project's hardware, not a variable to compare. The only comparison used to draw conclusions is QLoRA vs. zero-shot/prompting on the same model.

Planned Ablations & Where RAG Fits

Ablation (same model, same split)
  • Zero-shot → Vietnamese prompt → QLoRA
  • With / without OCR in the prompt
  • Original OCR order vs. TL-BR
  • LoRA rank r and target modules
RAG — conditional option

OCR in the prompt acts as “evidence retrieval” from the image itself. RAG with an external knowledge base (embedding + FAISS, top-k) is done only in W9 if error analysis shows that many errors are caused by knowledge missing from the image. In that case the knowledge base, embedding model, retrieval method and token budget will be specified.
