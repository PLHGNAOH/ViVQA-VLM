\section{Môi trường}

Mọi lần chạy dùng Google Colab Pro: GPU L4 24~GB cho huấn luyện, đánh giá và
prototype; GPU T4 cho dựng cache OCR. Thư viện chính: PyTorch 2.11.0 (CUDA 13.0,
bản Colab cài sẵn), Transformers 5.17.0, PEFT 0.21.2, bitsandbytes 0.50.2,
Accelerate 1.15.0, qwen-vl-utils 0.0.14 và Gradio 6.31.0. Hai lưu ý khi cài đặt:

\begin{itemize}
  \item \textbf{PaddleOCR GPU cài chung với PyTorch} có thể ghi đè thư viện NCCL
  của PyTorch làm \texttt{import torch} hỏng. Các notebook có sẵn quy trình bốn
  bước: ghi lại các gói \texttt{nvidia-*} của PyTorch, cài Paddle, cài lại NCCL
  của PyTorch, rồi kiểm cả hai trong tiến trình riêng.
  \item \textbf{VietOCR} cài bằng \texttt{pip install --no-deps vietocr==0.3.13},
  vì bản trên PyPI khóa phiên bản Pillow cũ.
\end{itemize}

Mỗi notebook được mở từ GitHub trên Colab, chọn đúng loại GPU ghi ở đầu notebook
rồi chạy toàn bộ. Notebook tự kiểm mã băm của dữ liệu, cache OCR và adapter trước
khi dùng GPU.

\section{Lệnh chạy}

Mọi notebook gọi hai lệnh nền dưới đây với tham số ghi sẵn. Ví dụ cho B3-full:

\begin{small}
\begin{verbatim}
python -m src.adaptation.train_qlora --dataset vitextvqa_official \
    --run_name <run> --epochs 1 --save_steps 100 \
    --mode ocr --ocr_backend paddledet_vietocr --ocr_template v1 \
    --ocr_max_chars 600 --ocr_min_conf 0.0

python -m src.eval.run_baseline --dataset vitextvqa_official \
    --data_file <.../test.json> --run_name <run_eval> --chunk 500 \
    --adapter <Drive>/adapters/<run>/epoch_1 \
    --mode ocr --ocr_backend paddledet_vietocr --ocr_template v1 \
    --ocr_max_chars 600 --ocr_min_conf 0.0
\end{verbatim}
\end{small}

Bỏ các tham số OCR (\texttt{--mode ocr} và \texttt{--ocr\_*}) thì thành B2 hoặc C3;
bỏ \texttt{--adapter} thì thành B1. Cấu hình chung (bf16, 4-bit NF4, tối đa 401.408
điểm ảnh, greedy, tối đa 32 token sinh, seed 42, LoRA $r = 16$ trên q, k, v, o) nằm
trong \path{configs/qwen_lora.yaml}. File \path{run_signature.json} ngăn việc chạy
tiếp một lần chạy dở bằng cấu hình khác.

Các phân tích (bảng đánh giá đầy đủ, kiểm định ghép cặp, ba seed, thí nghiệm
$2\times2$, ablation LoRA, POPE-vi, phân tích lỗi, kiểm tra EXIF) chỉ cần CPU và đọc
lại \path{predictions.json}; lệnh và notebook tương ứng được liệt kê trong
\path{docs/REPRODUCE.md}, mục 5.

\section{Prototype}

Giao diện chạy bằng notebook \path{28_prototype_v2_live_demo_sh_qwen25vl.ipynb} trên
L4; notebook kiểm lại các luật R-OCR và R-LIVE rồi mở đường dẫn Gradio. Có thể chạy
bằng dòng lệnh:

\begin{small}
\begin{verbatim}
python -m src.prototype.infer --official sh \
    --drive_root /content/drive/MyDrive/ViVQA-VLM \
    --image image.jpg --question "<cau hoi>" --out result.jsonl
\end{verbatim}
\end{small}

Tham số \texttt{--official sh} tự lấy adapter SH và kiểm mã băm; thêm
\texttt{--mock} để thử mà không cần GPU.

\section{Độ tất định và giới hạn đã biết}

Đánh giá dùng greedy và chạy từng câu. Chạy lại trên cùng loại GPU (L4) cho dự đoán
trùng 100\% (ví dụ 9.902/9.902 câu ở lần kiểm tra tuần 14). Đổi loại GPU (T4 và L4)
có thể làm OCR lệch nhẹ ở vài ảnh, nên cần dùng đúng loại GPU ghi trong notebook.
Các giới hạn đã biết:

\begin{enumerate}
  \item Một số thư viện (bitsandbytes, Accelerate, qwen-vl-utils) không được ghi vào
  log của từng lần chạy mà chỉ có trong ảnh chụp môi trường; hai lần ghi khớp nhau.
  \item PyTorch là bản Colab cài sẵn; nếu Colab đổi bản mặc định, cần cài đúng phiên
  bản ghi trong log.
  \item Cache OCR chính thức có lỗi EXIF ở 1,256\% câu test ViTextVQA; số chính thức
  giữ nguyên, kết quả sau khi sửa được báo như phân tích độ nhạy
  (mục~\ref{sec:res-exif}). Muốn tái lập đúng cache chính thức, dùng mã nguồn trước
  khi sửa (commit \texttt{b9f7fd4}).
  \item ViTextVQA có kiểm soát truy cập: người tái lập phải tự xin quyền.
\end{enumerate}
